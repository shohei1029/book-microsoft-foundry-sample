# Devagent Runtimeのロールバックと停止

ロールバックは、現在版の修正を待たず、直前の正常版へトラフィックを戻して影響を小さくする操作です。データ移行や外部副作用がある場合は、コードだけを戻しても安全とは限りません。

## ロールバックの判断

デプロイ時に設定した停止条件へ達した場合は、予定した判断者がロールバックします。例:

- Error rateが5分間2%を超える。
- P95 latencyが10分間5秒を超える。
- 重大な評価ケースが一件でも失敗する。
- 誤った外部操作またはデータ公開が疑われる。

セキュリティ事故の疑いがあれば、ロールバックと同時にGuardLineへ報告します。

## 操作手順

1. Deployment詳細で、Service、Environment、現在版、影響を確認します。
2. 「ロールバック」を選びます。
3. 戻すバージョンが直前のHealthy版であることを確認します。
4. Configuration setとConnectionの互換性を確認します。
5. 理由にインシデントID、観測した指標、判断者を記載します。
6. データ移行がある場合は、前方修正または復元手順の責任者を確認します。
7. 「ロールバックを開始」を選びます。
8. 状態がRolling backからHealthyへ変わるまで、トラフィックと指標を監視します。

## 緊急停止

どのバージョンでも安全に処理できない場合は「停止」を使います。確認画面で利用者へ返すメッセージ、キュー済み処理、再開責任者を確認します。停止後、エンドポイントが意図した保守応答を返すことを確認します。

## 復旧後

1. Error rate、P95 latency、評価、顧客影響が正常化したことを確認します。
2. `#runtime-status` と顧客連絡担当へ結果を共有します。
3. DeploymentのAuditへ、判断、実行者、確認者、時刻を確認します。
4. LaunchPadまたはインシデントへTrace、影響、暫定対策、次の対応を記録します。
5. 重大障害は5営業日以内に非難を目的としないレビューを作成します。

ロールバックできたことだけで問題を完了にしません。失敗版の再デプロイを防ぎ、原因と検出改善を追跡します。
