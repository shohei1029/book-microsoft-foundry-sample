# SourceNestのCI失敗対応とマージ

CIの赤い状態を再実行だけで緑にしようとせず、失敗したジョブ、最初の原因、ローカル再現を確認します。

## CI失敗を調べる

1. Pull Requestの「Checks」を開きます。
2. 失敗したPipelineを選び、「Pipeline詳細」を開きます。
3. Stage、Job、Statusを確認し、最初に失敗したJobを選びます。後続の取消は原因ではありません。
4. ログのエラー周辺と、使用したコミットSHA、実行環境を確認します。
5. 同じコマンドをローカルで実行します。
6. 自分の変更が原因なら修正し、同じ検証を通してpushします。

一時的なネットワーク障害や明示された基盤障害だけは「失敗ジョブを再実行」を使えます。同じエラーが2回続いたら再実行を繰り返さず、原因を調べます。

## レビューコメントへ対応する

1. コメントが質問、必須変更、提案のどれかを確認します。
2. 必須変更はコードとテストを修正します。
3. 採用しない提案には、要件、既存パターン、トレードオフに基づく理由を回答します。
4. 修正した会話へコミットまたは行を示し、レビュアーの再確認を待ちます。
5. 自分でレビュアーの会話を解決済みにしない運用では、レビュアーに解決を依頼します。

## マージ条件

- 必須CIがすべて成功している。
- 必要な人数と領域オーナーのレビューが承認済みである。
- 未解決会話がない。
- Target branchの最新変更を取り込んでいる。
- リスク、移行、リリースノートが更新されている。

## マージ後

1. SourceNestが表示するマージコミットと関連Issueを確認します。
2. デプロイPipelineを起動する変更では、対象環境と成果物バージョンを確認します。
3. Issueを完了へ変更し、必要な利用者連絡を行います。
4. ローカルの作業ブランチを削除します。

```bash
git switch main
git pull --ff-only
git branch -d fix/2841-tool-timeout
```

マージ済みでもリリースまたはデプロイが完了したとは限りません。担当製品のリリース手順で結果を確認します。
