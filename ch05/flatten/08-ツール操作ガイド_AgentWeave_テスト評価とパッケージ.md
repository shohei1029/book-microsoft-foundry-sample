# AgentWeaveのテスト、評価、パッケージ

Runtimeへ渡す前に、設定検証、コードテスト、エージェント評価を別々に実行します。一つのコマンドが成功しても、他を省略できません。

## 1. 設定検証

```bash
uv run agentweave validate
```

モデル接続、Tool定義、フロー参照、評価ファイルの構文を確認します。設定エラーは実装テストより先に直します。

## 2. コードテスト

```bash
uv run pytest
```

Toolの入力検証、分岐、失敗時の処理、外部APIのタイムアウトをテストします。実際の顧客システムを単体テストから呼ばず、契約に合うテストダブルを使います。

## 3. 評価セット

`evaluations/smoke.yaml`には、代表的な正常ケース、情報不足、対象外、Tool失敗、安全上拒否すべき入力を含めます。

```bash
uv run agentweave eval run evaluations/smoke.yaml
```

結果で次を確認します。

- 全体の合否と終了コード
- ケースごとのスコアと失敗理由
- 期待したToolと実際のTool
- 引用または根拠の一致
- 失敗時のTrace ID

終了コード`0`は合格、`1`はテストまたは評価の不合格、`2`は設定または引数の誤りです。不合格ケースを削除して合格にしません。仕様が変わった場合は、変更理由とレビューを伴って期待値を更新します。

## 4. パッケージ

3種類の確認が成功したコミットで実行します。

```bash
uv run agentweave package --output dist/
```

`dist/`に、不変の成果物とマニフェストが生成されます。マニフェストでコミットSHA、AgentWeaveバージョン、依存関係、評価結果の参照を確認します。`.env`、ローカルキャッシュ、テスト用の秘密が含まれていないことを確認します。

## SourceNestへ記録する

Pull RequestのValidationへ、実行した3コマンドと結果を記載します。成果物そのものをGitへコミットするか、PipelineのArtifactへ保存するかはリポジトリのREADMEに従います。

Runtimeへデプロイするバージョンは、ローカルで再ビルドせず、SourceNestの承認済みPipelineが生成した成果物を使います。
