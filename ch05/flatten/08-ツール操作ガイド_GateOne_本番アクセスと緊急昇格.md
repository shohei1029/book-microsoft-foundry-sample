# GateOneの本番アクセスと緊急昇格

本番アクセスは期限付きで取得し、通常作業と緊急作業を分けます。重要な変更では、操作する実行者と確認するレビュアーを別の人にします。

## 通常の本番アクセス

1. 関連するインシデント、変更、LaunchPadプロジェクトのIDを確認します。
2. GateOneの「申請」から「本番アクセス」を選びます。
3. 対象環境が `Production` であることを確認します。
4. 閲覧、デプロイ、接続管理など、必要なロールを一つ選びます。
5. 作業開始の15分前から、終了予定の30分後までを目安に期間を指定します。
6. 作業手順、停止条件、ロールバック、確認者を業務目的へ記載します。
7. 影響確認画面で、対象サービスと顧客が正しいことを再確認します。
8. 承認後、開始時刻になったらGateOneの「有効化」を選び、多要素認証を行います。

本番画面を開いたら、最初に環境バッジ、サービス名、現在のバージョンを確認します。依頼と異なる場合は操作しません。

## 緊急昇格を使う条件

現在進行中の重大障害または重大な脆弱性で、通常承認を待つことが顧客影響を広げる場合だけ使います。納期が迫っている、承認者が会議中、申請を忘れたという理由では使いません。

1. 「申請」から「緊急昇格」を選びます。
2. インシデントID、影響、対象、必要ロールを入力します。
3. `通常承認を待てない理由` と `最初に行う操作` を記載します。
4. 有効期間を最長2時間以内で指定します。
5. 多要素認証を行い、「緊急昇格を開始」を選びます。
6. Relayの `#runtime-status` へ、申請ID、実行者、確認者、次回更新時刻を共有します。

緊急昇格を開始すると、SecIT、対象システムオーナー、当番責任者へ通知されます。

## 作業後

1. 結果と現在の顧客影響を確認します。
2. GateOneで「アクセスを終了」を選びます。
3. インシデントまたは変更レコードへ、実施時刻、操作、結果を記録します。
4. 緊急昇格を使った場合は1営業日以内に、理由、通常手順との差、追加対応を記録します。

誤った対象へアクセスした、予定外のデータが見えた、監査ログが残っていない場合はGuardLineへ報告します。
